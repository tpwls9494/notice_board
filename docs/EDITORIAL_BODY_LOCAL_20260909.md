## 구현

- Signal.body: 선택적 Text 컬럼, 입력 길이 최대 20,000자. 기존 행의 기본값은 NULL.
- 새 마이그레이션: 202609060002 → 202609090001. 기존 제목·요약·활용 포인트·실습·댓글·관계 변경 없음.
- 새 본문은 소제목·표·목록·인용·코드·이미지를 지원한다. raw HTML은 렌더링하지 않고 Markdown URL 검사와 sanitize를 사용한다. 외부 링크는 noopener/noreferrer, 이미지는 no-referrer로 처리한다. 임베드·실행형 다이어그램을 추가하지 않았다.
- body가 있으면 기존 활용 포인트 대신 출력하고, body가 없으면 기존 표시로 돌아간다. 저장된 기존 필드는 지우지 않는다. 별도 직접 해보기는 내용이 있을 때 계속 표시한다.
- 관리자 검토함에서 본문 작성·미리보기·저장 가능. 목록 소개는 한 문장 안내로 수정.
- release/research는 try_this 없이 관리자 공개 가능. workflow는 기존처럼 실행 안내를 요구한다. 본문 또는 활용 포인트와 출처·검증 수준 검사는 유지.
- 새 body가 포함된 ingest는 자동 공개하지 않고 review 상태로 저장한다. 기존 수집 글의 자동 공개 조건을 완화하거나 수집기를 켜지 않았다.
- 원문은 본문 뒤, 댓글 앞의 기존 위치에 하나만 유지. 후기 연결과 댓글·대댓글은 기존 구현을 사용한다.

## 로컬 확인 흐름

1. 새 해설에서 도입부→소제목→요금제 표를 읽는다. 모바일 폭에서는 표 영역만 가로 스크롤된다.
2. 본문 아래 원문 링크가 하나인지, 그 아래 후기·댓글이 유지되는지 확인한다.
3. AI 활용법·논문 탭의 기존 글도 열어 기존 내용이 남아 있는지 확인한다.
4. 로컬 전용 관리자 계정으로 로그인해 댓글을 작성할 수 있다. Google 로그인은 이 환경에서 비활성이다.

미리보기 시작 설정: ../.local-preview/editorial-preview-20260909/compose.yml. Vite는 VITE_API_URL=http://localhost:18000을 설정하고 frontend에서 npm run dev -- --host 127.0.0.1 --port 5173 --strictPort로 시작한다. 테스트 데이터 볼륨은 보존했다.
